# Описание проекта

Проект решает задачу **регрессии**: по характеристикам объявления о продаже подержанного
транспорта (год выпуска, цена нового экземпляра, пробег, тип топлива, коробка передач,
число владельцев) предсказать запрашиваемую цену `Selling_Price`.

Исходная выборка: [Car Price Prediction (used cars)](https://www.kaggle.com/datasets/vijayaadithyanvg/car-price-predictionused-cars/data)
— 301 объявление, 8 признаков. Все цены указаны в лакхах индийских рупий (1 лакх = 100 000 ₹).

# Запуск

Для запуска проекта под ОС GNU/Linux необходимо выполнить команды:

```shell
git clone https://github.com/0legzuz/iis_sasha.git
cd iis_sasha
python3 -m venv .venv_car_price
source .venv_car_price/bin/activate
python3 -m pip install -r requirements.txt
```

Активация виртуального окружения:

```shell
source .venv_car_price/bin/activate
```

Деактивация:

```shell
deactivate
```

Запуск Jupyter для работы с блокнотом:

```shell
jupyter notebook eda/eda.ipynb
```

# Запуск MLflow

Эксперименты по настройке модели логируются в MLflow. Сервер поднимается локально,
хранилище экспериментов и реестр моделей — в СУБД sqlite.

Скрипт запуска лежит в `./mlflow/start_mlflow.sh`. Запускать **из каталога `mlflow`**:

```shell
cd mlflow
sh start_mlflow.sh
```

После запуска интерфейс доступен по адресу http://localhost:5000

Рядом со скриптом появятся база `mlruns.db` и каталог `mlartifacts` с сохранёнными
моделями — в репозиторий они не коммитятся.

Блокнот с экспериментами — `./research/research.ipynb`. Сервер MLflow должен быть
запущен **до** выполнения блокнота.

# Исследование данных

Находится в `./eda/eda.ipynb`.

## Действия на этапе очистки данных

* Удалены 2 полностью дублирующиеся записи (301 → 299)
* Обнаружено, что датасет содержит **не только автомобили**: в нём присутствуют мотоциклы
  и скутеры (Bajaj, Hero, TVS, Yamaha, Royal Enfield, KTM, Honda Activa). По названию модели
  записи размечены новым признаком `vehicle_type`: 199 автомобилей и 100 единиц
  двухколёсной техники
* Удалены 2 физически неправдоподобные записи: скутер Honda Activa 3g с пробегом
  500 000 км (41 667 км в год) и мотоцикл Honda Karizma с 213 000 км.
  **Итоговый размер выборки — 297 записей**
* От формального критерия «выброс = значение выше 1.5 IQR» отказались сознательно:
  он удалял 8 записей, включая Toyota Fortuner с пробегом 135 000 км и Toyota Innova
  с 197 000 км — для дизельных внедорожников это нормальный пробег
* Пропущенных значений в датасете нет, восстанавливать ничего не потребовалось
* Проверено, что `Selling_Price` нигде не превышает `Present_Price` — противоречий нет
* Типы данных приведены: номинальные признаки к `category`, `Owner` и `car_age` к `int8`,
  `Year` к `int16`, `Kms_Driven` и `kms_per_year` к `int32`
* Перед сохранением удалён столбец `Car_Name` — 98 уникальных значений на 297 записей,
  кодировать такой признак нечем (при One-Hot получится 98 почти пустых столбцов,
  при Target Encoding среднее считается по 3 наблюдениям). Полезная информация из него
  уже извлечена в виде `vehicle_type`
* Перед сохранением удалён столбец `depreciation` — он вычислен через целевую переменную
  и его использование в модели было бы утечкой целевой переменной (target leakage)

## Созданные признаки

* `vehicle_type` — автомобиль или двухколёсный транспорт, выделен из `Car_Name`
* `car_age` — возраст в годах (`2020 - Year`)
* `kms_per_year` — годовой пробег (`Kms_Driven / car_age`)
* `depreciation` — доля сохранённой стоимости (`Selling_Price / Present_Price`).
  Создан **только для анализа**, в финальную выборку не включён из-за утечки целевой переменной

## Выявленные закономерности

* `Present_Price` — доминирующий предиктор: корреляция с ценой продажи 0.876, у всех
  остальных признаков она ниже 0.33 по модулю (см. [график](./eda/correlation.png)).
  В логарифмических координатах связь близка к линейной
  (см. [интерактивный график](./eda/price_scatter.html), [png](./eda/price_scatter.png))
* **`Seller_Type` — ложный признак.** Разрыв средних цен между салонами и частниками
  в 7.5 раза (6.63 против 0.88) объясняется не типом продавца: таблица сопряжённости
  показывает, что салоны продают 193 автомобиля и ни одного мотоцикла, а частники —
  98 мотоциклов и всего 6 автомобилей. Подтверждение: коэффициент сохранения стоимости
  у обеих групп одинаков — 0.64 и 0.63 (см. [график](./eda/price_by_category.png))
* Тот же эффект сегмента у `Fuel_Type` и `Transmission`: дизель (10.10 против 3.29)
  и автомат (9.31 против 3.93) «дороже» лишь потому, что это более дорогие модели
  в новом состоянии (см. [график](./eda/price_by_category.png))
* Реальный ценовой фактор среди категориальных признаков — `Owner`: один предыдущий
  владелец снижает сохранность стоимости с 0.64 до 0.46
* Амортизация линейна, а не экспоненциальна: у автомобилей сохранность падает с 0.87
  на третий год до 0.37 на десятый — около 7 процентных пунктов в год, после 11–12 лет
  кривая выполаживается на уровне 0.2–0.27. У двухколёсных траектория та же
  (см. [график](./eda/depreciation_curve.png))
* Сильнейший фактор обесценивания — возраст: корреляция с сохранностью стоимости −0.856
  против −0.686 у суммарного пробега
* Обесценивает лот именно **суммарный** пробег, а не интенсивность езды: корреляция
  `kms_per_year` с сохранностью всего −0.205. Положительная корреляция `kms_per_year`
  с абсолютной ценой (0.321) — артефакт сегмента, дорогие машины больше ездят
  (см. [график](./eda/kms_vs_price.png))
* Целевая переменная скошена вправо (коэффициент асимметрии 2.53); логарифмирование
  приводит её к 0.11, но распределение становится двугорбым — левый горб это
  двухколёсные, правый автомобили (см. [график](./eda/target_distribution.png)).
  Обучать регрессию имеет смысл на логарифме цены
* `Year` и `car_age` — один и тот же признак с противоположным знаком (корреляция −1.00),
  в модель нужно подать только один из них
* `Present_Price` и `car_age` практически не связаны (0.06) — признаки несут
  независимую информацию

Обработанная выборка сохранена в файл `./data/clean_data.pkl`.

# Результаты исследования

Эксперименты проведены в `./research/research.ipynb`, все прогоны залогированы в MLflow
(эксперимент `Car Price Regression`).

## Сравнение экспериментов

Выборка разбита на обучающую и тестовую в пропорции 75/25 со стратификацией
по `vehicle_type` — в данных два разных рынка, и без стратификации метрики
были бы несопоставимы между прогонами. Метрики посчитаны на тестовой части.

| Конфигурация | mae | mape | mse |
|---|---|---|---|
| baseline | 0.6496 | 0.1569 | 2.2717 |
| **feature_engineering** | **0.6419** | **0.1548** | 2.3996 |
| feature_selection | 0.6592 | 0.1618 | 2.2939 |
| optuna_tuned | 0.6484 | 0.1555 | 2.2718 |

Основная метрика — `mae`: она выражена в тех же единицах, что и цена (лакхи рупий),
и потому интерпретируется напрямую.

## Лучшая модель

Лучший результат показала модель **`feature_engineering`** — случайный лес с параметрами
по умолчанию на расширенном наборе признаков: **mae = 0.6419**, mape = 0.1548.

Средняя ошибка — **0.64 лакха при медианной цене 3.80 лакха**, то есть около 15%.

Наблюдения по ходу экспериментов:

1. Генерация признаков (`PolynomialFeatures` для `Present_Price`, `car_age`,
   `kms_per_year` и `KBinsDiscretizer` для `Kms_Driven`) расширила набор
   с 9 до 19 признаков и дала лучший `mae`.
2. Отбор 9 признаков из 19 методом `SequentialFeatureSelector` (mlxtend, forward)
   качество **не улучшил** — mae вырос до 0.6592. Отбор отбросил сам
   `Present_Price`, главный предиктор (корреляция 0.876), оставив вместо него
   производный `poly__Present_Price^2`.
3. Подбор гиперпараметров `optuna` (15 испытаний, минимизация mae по кросс-валидации)
   дал mae = 0.6484 — лучше baseline, но хуже простой генерации признаков.

Разброс между всеми четырьмя конфигурациями невелик (mae от 0.642 до 0.659, около 3%).
На выборке в 297 записей такая разница близка к уровню шума, и ожидать существенного
выигрыша от настройки не приходится: качество определяется в первую очередь тем, что
`Present_Price` почти напрямую задаёт цену продажи.

### Отобранные признаки на шаге feature_selection (9 из 19)

```
numeric__car_age             poly__car_age
categorical__Fuel_Type       poly__Present_Price^2
categorical__Owner           poly__car_age^2
categorical__vehicle_type    poly__kms_per_year^2
kbins__Kms_Driven
```

Индексы: `2,4,7,8,10,12,15,17,18`

Тот же отбор методом `RFE` (движется в обратную сторону — удаляет наименее важные)
совпал с `SFS` лишь на **4 признаках из 9 (44%)**. Совпадение — всё, что связано
с возрастом (`car_age`, `poly__car_age`, `poly__car_age^2`) и `poly__Present_Price^2`.
При этом `RFE` сохранил исходный `Present_Price` и его произведения, а `SFS` предпочёл
категориальные признаки. Низкое согласие объяснимо: признаки сильно коррелированы между
собой, и при почти равном качестве алгоритмы выбирают разные эквивалентные наборы.

## Production-модель

Финальная модель обучена на **всей** выборке (297 записей, 9 исходных столбцов)
и зарегистрирована в реестре `car-price-rf` как **версия 3** с тегом `Production`.

```
run_id = 54b54fccbed044c5af3fe62db2c20163
```

Обращаться к ней можно по алиасу: `models:/car-price-rf@Production`

Используемые столбцы: `Present_Price`, `Kms_Driven`, `Fuel_Type`, `Seller_Type`,
`Transmission`, `Owner`, `vehicle_type`, `car_age`, `kms_per_year`
(см. `research/production_columns.txt`).

Скриншоты интерфейса MLflow и файл описания модели:
[прогоны с метриками](./research/model_runs.png),
[версии модели](./research/model_versions.png),
[MLmodel](./research/MLmodel).

> Совместимость проверена — оба блокнота выполняются в одном окружении без ошибок.
